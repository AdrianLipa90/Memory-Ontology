# PNAML Native PNV — existing terminal execution route

This route reuses the unmodified, upstream PNCS native PNV interpreter. It is not a new Python implementation of PNCS or a new NOEMA engine. PNV remains the program representation; the upstream interpreter's host language is an existing implementation detail. Do not replace PNCS/PNV semantics with another language, add substitute callbacks, infer KAKU/RADICAL identities, or introduce new infrastructure without the operator's prior agreement.

1. Discover the actual available terminal or existing PNAML operator. If a local terminal is available, locate the original interpreter and the requested exact PNV program in the installed plugin files. If they are not mounted, obtain the exact authorized source files through supported source retrieval/materialization; do not assume a downloaded archive or a tool exists. No new hosting or server is required for this terminal route.
2. Verify the interpreter against `references/SOURCE_MANIFEST.json` and preserve exact program bytes. The existing `parse_pnv` and `execute_pnv` interfaces are the execution authority for this narrow PNV-1 route. Use the existing interpreter from the terminal with explicitly supplied admitted source values and, only when already available and admitted, registered comparators/transforms. Do not implement a replacement interpreter or invent missing bindings. A parsed program is not an executed program.
3. Preserve source and admission boundaries. The bundled memory gate compares static, supplied observation records; it cannot independently establish that the source observations are genuine or that the experiment occurred. The supplied test receipt is synthetic, not an observation of live NOEMA. The interpreter generates deterministic receipts for its results: do not use this route to hash or continuously archive evolving AUX state. Use the applicable native NOEMA/PNAML observation contract for live data.
4. Return the actual interpreter result, assertion status, deterministic receipt, source identifiers, and unresolved bindings. A missing transform is a binding problem, not a timeout; do not bypass it. The bundled Collatz candidate has no admitted `collatz.parity` binding in this test environment. Its parse succeeds, execution stops at that operation. Native PNCS/NOEMA registration and execution remain separate from this narrow terminal route.
5. If the terminal or required files are unavailable, state the exact limitation. Packaging these files does not automatically expose MCP tools in ChatGPT Mobile or establish a connection to a persistent NOEMA producer. Do not claim a working connector, continuous stream, or native host execution solely from this skill.
