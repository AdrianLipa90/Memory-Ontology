## Exact specialization, not a replacement definition

The source defines character as the weighted average of comparable choice policies over a declared historical window. Step 1 takes only unit weights, deterministic policies, one declared query domain, two distinct fixed candidate labels and an explicitly selected growing observation window. For selected choices c_s in {a,b}, N_a=sum_s 1[c_s=a], N_b=sum_s 1[c_s=b], N=N_a+N_b. The exact representation is K=((N_a,N),(N_b,N)), i.e. two rational numerator/denominator pairs, not floating point and not a physical or moral score. The update is N'_a=N_a+v_a, N'_b=N_b+v_b, N'=N+1, where the observation owner supplies the typed one-hot choice (v_a,v_b) and its label. PNV computes the arithmetic and emits the compatibility witnesses. No default weights, window length, candidate labels or character-based action rule are installed. The empty checkpoint has N=0 and no character probability readout; the first admitted observation makes N=1.

The [PNV program](native/PIP_CHARACTER_DEPOSIT_STEP_V0_1.pnv) emits CHARACTER, CHECKPOINT, LINEAGE, WITNESS. The checkpoint records owner, query domain, ordered candidate pair, two counts, total and previous observation reference. LINEAGE retains previous/current observation references and the original Hotel occurrence. A mismatch remains observable as a false witness; the emitted arithmetic candidate is not an admitted checkpoint. No ASSERT, no scheduler, no new runtime admission or AUX restriction. Typed nonnegative exact integer counts, actual source identity, valid domain/candidate labels, and unique selected occurrences are source preconditions. Last-reference inequality alone is not a global deduplication or order proof. PNV equality does not establish source authentication or independently validate all types. The program is a finite read-only operator on immutable observations and does not read/hash a dynamic AUX. No runtime storage writes or action effects.
