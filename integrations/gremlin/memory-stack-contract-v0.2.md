# GREMLIN Memory Stack Contract — v0.2

## Pipeline

GREMLIN consumes Memory Ontology objects through the following fail-loud path:

\[
\text{EVENT}
\to\text{TRACE}
\to\text{typed relational graph}
\to\text{orbital address}
\to\text{projection family}
\to\text{correlation}
\to\text{retrieval/reconstruction}
\to\text{candidate completion}
\to\text{verification}
\to\text{receipt}.
\]

## Required separation

GREMLIN MUST preserve these states as distinct:

- RECALLED
- RECONSTRUCTED
- INFERRED
- IMAGINED
- INSUFFICIENT_EVIDENCE
- CONFLICT

A candidate generated by imagination cannot mutate historical memory merely because it has high coherence.

## Provenance rule

Every durable projection MUST carry a provenance commitment. A RECALLED result requires a verified historical provenance chain.

A RECONSTRUCTED result requires:

1. at least the declared minimum support;
2. agreement on the invariant commitment;
3. compatible orbital address classes;
4. explicit list of contributing projection identifiers;
5. a reconstruction receipt.

## Graph correlation

GREMLIN may rank candidate neighborhoods by relational compatibility. Phase or orbital coordinates may change search order or admissibility but MUST NOT erase conflicting evidence.

## Imagination

Imagination is constrained graph completion:

\[
\hat G=\arg\max_{G'}\operatorname{coherence}(G'\mid G_{known},C).
\]

Its output authority is CANDIDATE_ONLY until separately validated.

## Degradation behavior

Partial projection loss should degrade reconstruction confidence/support before destroying the memory invariant. Ambiguous equal-support conflicts MUST fail loudly.

## Security / integrity

- no silent promotion of generated candidates;
- no provenance rewriting;
- no collision-based aliasing between incompatible memory IDs;
- no phase-wrap mismatch for equivalent \(U(1)\) addresses;
- no dependence on a single storage node for a memory declared holographically reconstructable.
