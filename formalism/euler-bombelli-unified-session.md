# Unified reflective session — executable offline profile

Author research direction: Adrian Lipa. Base 03c2f66 (v1.3 merged).
One entry point: [reflective_session.py](../projects/pip-project/integrations/pnaml/reflective_session.py).
The existing PNCS/PNV graph is semantic authority, original GUIDE selects
routes, original coupled source model owns 36D evolution, original Hotel
assigns indices and the existing PNAML MemoryStore owns durable records.
Python is host orchestration glue, not a new language, engine, dispatcher,
memory law or implementation of PNV. No new database schema.

## Run

Install the pinned upstream PNCS and TCD packages and existing variant
requirements as in the existing pip-tcd-affective-hair CI workflow.
From the repository root (use a new dedicated offline journal):

    python projects/pip-project/integrations/pnaml/reflective_session.py \
      --journal /tmp/pip-reflective.sqlite --tcd-root _tcd --variant mobile --episodes 3

Repeat exactly the same command in a new process to continue from 3 to 6.
The profile verifies the journal, reproduces the original synthetic model
from the declared seed/dt and selected immutable commands, checks each
semantic result, reconstructs learned route weights, exact Hotel lineage,
character, intention window, Collatz, RDSS edge and orbital state, and
then consumes new input. Replay creates a new software producer generation;
original historical references retain the original generation and sequence.
This is deterministic reconstruction of a finite declared source model,
not resurrection of a physical trajectory or restoration of arbitrary
live producer state. One writer for this offline journal. Do not use a
user's existing operational journal.

## Dataflow

Original Model + Coupler (HTRI, QHTRI, Q28, RDSSG) -> actual frame -> original
TCD projection and PNLF phase9 readout. Original PNV linked graph receives
the previous and current typed theory, independently measured synthetic
environment edges, actual prior allocation history and GUIDE-selected
action. Proof and correction drive the prospective context; computed
GO enables the actual successor. Actual arrival or failure drives the
original procedural trace law. Successful arrival changes original
AdaptiveEdge and tagged Collatz state. Selected synthetic phase coupling
is computed with the original RDSS phase_step and passed as an explicit
relative producer increment to the original Model on the next tick.
Original FS displacement and Kepler segment evolve the reference orbit.
The existing Character Depository updates from comparable GO/HOLD
observations; availability unknown and withdrawal do not count.
The original Hotel successor is checked against the integrated graph.
All these calls are in one session, not isolated example invocations.

The chosen synthetic route geometry, initial allocations, coupling gain
.2, kick scale .05 and observation map (one selected phase pair) are
explicit test profile constitutive choices. The v1.2 limited route policy
does not use the truth of a theorem as permission, and the TCD projection
is contextual/readout, not a truth source or production action selector.
No claim of a new calibrated geometry or general theorem prover.

One selected episode record contains source refs, typed inputs, proof
certificate, outcomes, categorical TCD reference, exact character counts
and Collatz lineage. No raw phase, velocity vectors, coupling arrays,
dynamic AUX hash or live data are written. Procedure.apply_trace hashes
only isolated synthetic procedural snapshots under the original source
runtime, never the evolving AUX. On failed in-memory execution, reopen
from journal; commit precedes Hotel publication, so committed events are
replayed once. Duplicate immutable input returns the old result without
advancing. A collision rejects. Recovery assumes one writer, same source
version, same profile and numerical environment; no operational distributed
atomicity or real-machine recovery claim.

## Acceptance

Existing Mobile and Semantic CI run the single entry point, matched
restart (phase and orbit), duplicate test, HOLD/REVISE, interruption
after durable commit before Hotel advance, and actual separate-process
CLI continuation against uninterrupted six-episode reference.
Native producer registration, live Ternary Socket TX/RX, arbitrary live
PAUX exact checkpoint, actual host scheduler and unresolved general
PNCS transforms are not delivered by this offline profile. The previous
v0.9 PAUX CI checkout still needs repository access; do not publish private
source to work around it. No plugin release or live NOEMA mutation.
